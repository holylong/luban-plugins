# CSV / TSV 预览与解读

## 什么时候用

- 用户拖来或打开一个 `.csv` / `.tsv` / `.tab` 文件，问「这是什么数据」「帮我看看有没有问题」
- 需要从导出表里取数、过滤、汇总，或要把表格结果写回文件
- 用户贴了一段表格文本但列全挤在一起（多半是分隔符猜错了）

## 先看格式，别急着解析

1. **读前 5 行原始字节**，不要先 `pandas.read_csv` 再问为什么错：

   ```
   head -c 400 数据.csv | od -c | head
   ```

   看三件事：BOM（`EF BB BF`）、行尾是 `\r\n` 还是 `\n`、第一行的分隔符到底是逗号、Tab、分号还是竖线。
2. **分隔符**按第一行出现次数最多的候选判断（`,`、`\t`、`;`、`|`），但引号内的逗号不算：`"Smith, John"` 是一个字段。
3. **编码**不是 UTF-8 时（中文变乱码、`?`、`锟斤拷`），先试 GBK/GB18030：

   ```
   iconv -f GB18030 -t UTF-8 数据.csv > /tmp/utf8.csv
   ```

   只读不改原文件；要写回时显式问一句用哪种编码。

## 表格预览

- 桌面版（luban 2.9.8+）对 `.csv` / `.tsv` / `.tab` 有内置「表格预览」：标题栏按钮或 `⌘/Ctrl+Shift+V` 切换，首行当表头、行号固定、数字右对齐，超过 400 行 × 60 列会注明省略了多少。**它只是显示**：改数据仍然要改文件。
- 在对话里回答时用 Markdown 表格，并且：
  - 最多 10 行、8 列，超出就写「共 N 行，这里只看前 10 行」，再用分组/汇总说明整体
  - 列多时先给「列清单 + 一行示例值」，不要把所有列塞进一张表
  - 数值列右对齐靠不住时，别手工补空格，直接给统计

## 按列诊断

抽样（大文件不要全量读）：

```
head -n 200 数据.csv | tail -n +2      # 跳过表头看 200 行
wc -l 数据.csv                        # 只有行数，不加载内容
```

对每一列回答四个问题，取一小段样本即可：

| 问题 | 怎么看 | 常见坑 |
| --- | --- | --- |
| 类型 | 全是数字 / 日期 / 枚举 / 自由文本 | `1,234`、`007`、`1e6`、空串混在数值列里 |
| 空值 | 空串、`NULL`、`N/A`、`-` 都算缺失吗 | 只把空串当缺失会漏统计 |
| 唯一值 | `cut -d, -f3 数据.csv \| sort -u \| wc -l` | ID 列唯一 ≠ 分组列 |
| 异常 | 日期越界、负数、超长文本、前后空格 | 前导零被当数字丢掉（邮编、手机号） |

日期列写清格式（`2026-01-02` 还是 `2026/1/2`），否则后续比较会静默错。

## 回答的形状

1. **一句话结论**：这是什么表、多少行多少列、能不能直接用。
2. **列清单**：列名 → 含义 → 类型 → 是否有缺失。
3. **数据问题**：能复现的具体值（「第 41 行 city 为空」「price 有 3 行是 `-1`」），不要泛泛说「数据质量一般」。
4. **下一步**：给出可直接运行的一条命令或一段代码（awk / csvkit / python），并说明它只读不改。

## 不要做的事

- 不要为了「看清楚」把 20 万行全量加载再打印；先抽样、先统计。
- 不要把 CSV 当 JSON 逐行手写解析，引号、转义和单元格内换行会立刻打脸。
- 不要在没确认编码前用文本编辑器批量替换，一次保存就可能把整列中文变成乱码。
- 不要安静地改用户文件：写回时保留原文件，输出到新路径或先备份。
